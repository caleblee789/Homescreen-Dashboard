# Home Dashboard Overhaul 1.5.3 contact-sheet audit

Audit date: 2026-08-15

## Inspection scope and baseline integrity

The immutable acceptance baseline is `qa/live-ui-acceptance-1.5.3-release-2026-08-15`. It exists and contains the canonical exact-package evidence for Anki Desktop 26.8.1: 61 raw captures, 20 overview/detail contact sheets, three machine-readable suite reports, and the packaged add-on. The package SHA-256 recorded by both the sidecar and `release-evidence.json` is `68705bc06dabd277130600f14db0c8dc907dc3b39177778a784aaaa275d01dee`; the archive contains 23 allowlisted files. The suite split is 28 Calendar captures, 12 Study Insight captures, and 21 Settings/Restart captures.

The audit covered each suite overview, every full-resolution detail sheet, and raw captures where text, state, placement, or scaling needed confirmation. It also covered the baseline README, `release-evidence.json`, `calendar-report.json`, `insights-report.json`, `settings-report.json`, fixture descriptions embedded in those reports and probes, `qa/calendar_surface_manifest.json`, the three live acceptance probes, report validation, and relevant model, renderer, controller, settings, repository, static-asset, and JavaScript tests.

Source-sheet mapping is deterministic:

- Calendar overview contains CAL-01 through CAL-28; detail sheets 01 through 07 contain consecutive groups of four.
- Study Insight overview contains INS-01 through INS-12; detail sheets 01 through 03 contain consecutive groups of four.
- Settings initial overview contains SET-01 through SET-20; initial detail sheets 01 through 05 contain consecutive groups of four.
- Restart overview and restart detail sheet 01 contain RST-01.

The contact sheets are authoritative evidence of the released surface area, not a target design. No file in the 1.5.3 baseline was overwritten, renamed, deleted, or regenerated during this audit. Every candidate requirement below means a new exact-package capture outside that baseline, with its stable ID registered exactly once. An unavailable value must remain explicitly unavailable; it must never be rendered as zero.

Test shorthand used below:

- **C-live:** `qa/acceptance_probe_calendar_polish.py` plus `qa/validate_calendar_report.py`; **C-model:** `tests/test_calendar_model.py`, `tests/calendar_model_test.js`, `tests/test_calendar_repository.py`, `tests/test_calendar_manager_model.py`, `tests/test_calendar_qa_manifest.py`, and relevant renderer/static tests.
- **I-live:** `qa/acceptance_probe_insights.py`; **I-model:** `tests/test_insights.py`, `tests/test_controller_insights.py`, `tests/test_insights_qa_contract.py`, `tests/calendar_model_test.js`, and relevant renderer/static tests.
- **S-live:** `qa/settings_acceptance_probe.py`; **S-model:** `tests/test_settings_model.py`, `tests/test_config_and_themes.py`, `tests/test_verse.py`, `tests/test_calendar_qa_manifest.py`, and relevant static tests.
